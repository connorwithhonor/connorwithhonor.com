A.Permission Ladder card

Every task an agent runs is placed on a rung first. Print this and keep it next to the monitor.
RungWhat the agent may doReal estate examplesWho may run it

2. Draft-onlyWrite, but never send.Seller update. Repair request response for review. Buyer-agent FAQ.Anyone on the team
3. Act-with-approvalPropose an action and wait for a click.Calendar entry for a contingency. A reminder. A CRM task.Licensed agent
4. Act-within-limitsAct without a click, inside written limits, on low-risk sends only.Monday showing report to the seller if nothing changed and the checklist passed.Licensed agent, by written exception, after one clean month at rung 3

Never, on any rung

  • Sign anything.
  • Send an offer, counter, or contract document.
  • Give legal or tax advice, or interpret contract language beyond quoting it.
  • Contact any party about money.
  • Move, delete, or share a client file outside the approved workspace.

Earning a rung

A task moves up one rung after a documented month with zero rejected outputs at its current rung, and only with the approver's written sign-off. A task moves down a rung the day it produces an error. No exceptions.

B.Six questions for any vendor, and what a good answer sounds like

Ask in writing. Keep the answers in the brokerage layer. If a vendor cannot answer all six, client files do not go in.
Encryption
Data encrypted in transit and at rest. They can name the standard.
Retention
You can set how long conversations and files are kept, and delete on demand. They can show you where.
Training on our data
Your data is not used to train their models, and this is the default or a setting you control. In writing.
Admin controls
An administrator can manage users, roles, and what is connected, and can remove a user in one step.
Audit logs
Actions taken by agents are logged with timestamps and are exportable. The broker can read them.
Data location
They can tell you where the data lives and under which jurisdiction.

C.Transaction Desk agent job card

Paste into an agent-capable workspace that has read access to one test folder. Nothing else connected for the first run.
AGENT JOB: Transaction Desk PERMISSIONS: Read-only on the escrow folder. Draft-only for any message. Act-with-approval for calendar entries and reminders. No sending. No signing. No contact with any party. STEP 1 (read-only): Read the folder. Summarize the transaction in ten lines: parties by role only, acceptance date, price as stated, contingencies and their day counts, open items. STEP 2 (read-only): Build the task list keyed to the acceptance date. One row per deadline: task, due date, who owns it, source document. STEP 3 (draft-only): Draft the seller update in my voice using only the folder. Label anything not in the folder MISSING. STEP 4 (act-with-approval): Propose calendar entries for each contingency deadline with a reminder two business days prior. Ask me to approve each one. Add only what I approve. STEP 5 (log): List every file you read, every draft you produced, every action you proposed, and every approval you received. NEVER: Give legal or tax advice. Interpret contract language beyond quoting it. Contact any party. Move, delete, or share any file. Act on anything outside this folder.

G.Seven-day challenge

Read-only first. Always.
  • Day 1: place five weekly tasks on the Permission Ladder.
  • Day 2: ask your platform vendor the six questions, in writing.
  • Day 3: build the brokerage layer starter: policies, one forms guide, one local knowledge page with sources.
  • Day 4: run the Transaction Desk on the fictional folder, read-only.
  • Day 5: run the draft-only step. Read every MISSING.
  • Day 6: run act-with-approval on a test calendar. Approve one. Reject one. Read the log.
  • Day 7: write your 12-month plan. Put the monthly audit on the calendar.
